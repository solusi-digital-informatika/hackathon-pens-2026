## Database rules

- Database: PostgreSQL container on host 127.0.0.1 port 5435. If the container is stopped, agents may start it (`docker start` or run) automatically. If Docker is unavailable in the environment, fallback gracefully to SQLite/test db so automation never stops.
- Databases: `aioffice` (development) and `aioffice_test` (tests). Tests use `aioffice_test` only, never `aioffice`.
- Host 127.0.0.1, port 5435, user `aioffice`. The password and full URLs live only in backend/.env (git-ignored), as `DATABASE_URL` and `TEST_DATABASE_URL`. Commit a backend/.env.example without secrets. Never print or log the password.
- Never block execution on connection retry; ensure database is up or spin up test tables automatically.
- Create tables at startup via SQLAlchemy metadata. No migration tool in F1.

## Decisions on contract mismatches and open questions

1. `description` is optional in both API and UI.
2. UI label is "Project name"; the API field stays `name`.
3. API stores status in lowercase; the UI shows Title-case labels through a mapping.
4. Brief and shot data will come from separate endpoints in later milestones. F1 implements none of them. The Project Overview shows static placeholders ("No brief yet", "No shots yet").
5. The UI shows a fallback banner for 500 and network errors, and inline messages for 400 field errors.
6. `status` enum: `draft`, `active`, `archived`. Default `draft`.
7. `name`: trimmed, 1 to 100 characters, whitespace-only rejected. `description`: trimmed, at most 500 characters.
8. `GET /projects` supports `limit` and `offset`: default limit 20, maximum 100, sorted by `created_at` descending. The response includes `total`.
9. Duplicate project names are allowed. Identity is the unique ID.
10. No authentication in F1 (single user). An unknown project ID returns 404 with the standard error body.
11. Isolation: application-level scoping by `project_id` for all future project-owned data.

Also decided:

- CORS allows only http://localhost:5173 and http://127.0.0.1:5173.
- Frontend reads the API base URL from `VITE_API_BASE_URL` (default http://127.0.0.1:8000).
- Every non-2xx response uses one error body shape, as defined in api-projects.md.
